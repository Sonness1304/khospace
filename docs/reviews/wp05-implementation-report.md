# WP05 — Atomic holds and stable rental accounts

October28,2026. Base `fb851b91c453b314eba83ea1672eea3a3b3743ba`. Sole writer Jarvis inline; Atlas remains inactive after credit failure. Approved FR-011/012/013/014/045. This package introduces holds, booking status/confirmation/cancellation and interfaces consumed by WP06/WP09, not a complete paid-rental workflow.

Holds acquire all sorted persistent unit parent locks, read databaseUTC afterwards, recheck quote expiry/version, facility/unit eligibility, local rental dates, current sellable rate/area/policy drift and allocation/overdue-occupancy predicates. Changed accepted terms return REQUOTE_REQUIRED. A future-only tariff version does not invalidate the currently sellable quote simply because aggregate rowversion changed. Successful holds freeze immutable quote terms for15 minutes and create one stable RentalAccount. Duplicate command results are transactional; a different key for an existing live booking from the same quote returns that existing booking. New explicit hold after logical expiry creates a new booking/account while retaining the original account. Quote expiry remains separate from hold expiry.

Booking mutations lock sorted units→Booking→RentalAccount; cancellation/confirmation use the same order and database time. Logical expiry is recognized by allocation checks and status without requiring a cleanup job. Confirmation is Sales+facility only and refuses expired holds and missing verified deposit; repeated confirmation returns the existing booking. Cancellation is CustomerAdmin/Sales, versioned, releases allocations atomically, retains account/funds-review state and invokes the shared Scheduled-lease cancellation interface. WP06 must replace the no-lease-module implementation with actual Scheduled-lease/occupancy checks before lease conversion ships.

**No production payment bypass:** IDepositVerification defaults fail-closed (Verified=false,Amount=0), even if rounding makes required deposit0. Only test DI replaces it with SyntheticVerifiedDeposit; no HTTP endpoint fabricates received money. WP09 must register real verified fund/account data and test cancellation/verification races. These future finance tests are not claimed complete by this package. UI states verification unavailable until that integration; no fake paid status.

BookingLine now exists and SpaceAllocation references a same-unit composite BookingLine FK. Earlier allocation-predicate fixtures were updated to construct real synthetic Quote/Booking/Account/BookingLine parents; no integrity check removed to keep tests green. UnitOccupancy's real lease owner FK remains WP06.

UI provides explicit15-minute hold acceptance, current server status/deadline, original account/deposit, cancellation reason and readback. Lost/5xx mutation replies keep the frozen original key/payload/version; readback first, explicit same-key retry after404. A failed retry cannot erase prior uncertainty. Context changes hide foreign booking details and cannot rebind pending ownership. Known save followed by failed GET stays saved. State/deadline is a server observation; full live countdown/timeline and staff workspace navigation remain WP10.
