Implemented facilities/zones/fixed units, positive fixed-precision m², same-facility zone FK and unique codes, publication, VND daily sales-rate versions, maintenance and shared allocation/physical-occupancy predicates. Public projections expose published units with a currently sellable rate, never customer identities. Search validates local DateOnly [start,end),1–365 days/minimum area, pages by unique unit code, ignores expired holds and refuses unresolved overdue occupancy. Search is explicitly indicative, not a reservation.

UnitLockService requires the caller's SQL transaction; validates1–20 distinct nonempty IDs, acquires persistent unit parent UPDLOCK/HOLDLOCK individually in sorted order, then reads databaseUTC. Maintenance locks all units before conflict checks/inserts and audits the entire command. Opposite-order sets use the same order even with no prior child allocations. Area changes are blocked by future commitments/maintenance or uncleared occupancy. Rate changes serialize on the same parent, close the previous sales window, reject overlaps, bump aggregate rowversion and recheck local date using SQL time after locks. One rate creation per unit/sales-start date; same-day replacement is refused, preserving explicit historical versions.

Operational commands use a transaction-owned per-actor/scope/key SQL application mutex to serialize initially absent receipt keys; this does not replace unit locks. The business mutation/audit/saved JSON receipt commit together. The same key with changed operation/payload/precondition returns409. Key reuse across operations in a scope is intentionally rejected rather than overwriting another command. GET command readback is restricted to the initiating actor and current facility access. Missing mutable precondition428/stale412.

UI A includes facility selection, dates/minimum area search, pagination, empty/error/stale results, explicit manager context, unit create/edit, dated rates and multi-unit maintenance. CSRF/cookie/version/idempotency headers come from current server contracts. A lost mutation reply keeps its command identity, blocks new mutations and offers saved-result readback; no automatic POST replay. Context switches invalidate incompatible records and ignore stale read replies. Facility/zone configuration is available through scoped APIs; further complete configuration/navigation UI is part of WP10 integration.
