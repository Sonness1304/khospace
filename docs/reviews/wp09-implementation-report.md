# WP09 — Manual verified funds and immutable rental statements

October28,2026. Base97fc6f6aa31d66ee9090b128a8fd1019c8802804. Sole writer Jarvis. FR-030/031/032/035. No live payment integration, refund transfer or tax assumptions.

Manual receipts record account/customer/facility, whole-VND amount, method/reference, actual received date and evidence reference. Finance must verify evidence explicitly before any allocation. Organization/method/reference uniqueness prevents duplicate records. Existing synthetic finance@example.test receives only facilityA Finance scope. Receipts bind to one stable RentalAccount in P0; allocations stay in that same account and customer. Splitting a single transfer across multiple rental accounts is not supported in P0 and must not be faked by duplicate references. This implementation ruling keeps cancellation/late funds and every target under one account lock; cost is manual reconciliation for cross-account transfers in a later scope.

All finance writes acquire persistent sorted units→booking/account→receipt→target, same as booking cancellation/confirmation. Positive allocations cannot exceed verified unapplied receipt money or deposit/charge outstanding; deposit credits have an append-only separate journal. Real VerifiedDepositReader replaces the unavailable production seam. Booking confirmation requires allocated full security while hold is live; mathematically zero rounded deposit requires explicit finance verification without fictitious money. Verified but unallocated receipts are retained, and cancellation/expiry mark refund review even if no deposit allocation occurred. Cancellation and verification serialize to the same retained account, never restore expired capacity or claim refunds paid.

Statements issue only after activation, one lease/calendar-month business key, with immutable exact LeaseVersionLine dates/days/area/rate/amount source snapshots. No recomputation or deposit revenue. Finance explicitly supplies the due date (month start through following year); duplicate generation returns the same ID, conflicting due-date edits409. Issued statement/line and journals reject application updates/deletes; verified receipt evidence is immutable except version-touch UpdatedAt on allocation. Paid/PartPaid/Unpaid and overdue derive from issued amount minus charge allocations and SQL local date, with no stock/lease termination side effect.

UI reads accounts, receipts and statements, shows held security/rental debt/unapplied/refund review separately, explicit evidence check, current versions and frozen command readback/retry. Exact amounts stay strings, including values beyond JavaScript safe integers. Context change clears finance identifiers/evidence/form drafts and hides prior data; pending commands retain original ownership for recovery. Responses arriving under a different context cannot fill its forms. Full list pagination/navigation is completed in WP10.
