# Private documents (WP16B)

Lease attachments inherit the lease organization/facility. Active customer members and FacilityManager/OperatorAdmin can upload/read; only CustomerAdmin or FacilityManager/OperatorAdmin can revoke. Lists are paginated at 50. Every download resolves current membership and scope; a previously known ID is not authorization. Revocation and membership writers serialize with download authorization through the transaction-owned identity lock. An already-authorized response in flight cannot be recalled.

The local implementation stores bounded binary content in the same SQL database as metadata and a random storage key. No user-supplied storage path, static file route or public URL exists. SHA-256 is checked before serving. Downloads use Content-Disposition attachment, no-store, nosniff and sandbox CSP. Blob/metadata/audit changes commit together. Original files remain immutable; revocation retains evidence. Destructive migration downgrade refuses existing private documents.

Upload accepts base64 JSON with a bounded request and at most 10 MiB decoded bytes. Safe ASCII basenames, matching extensions/MIME, PNG container/CRC/dimensions, JPEG marker/dimension and PDF header/EOF/common-active-name checks reject common invalid content. These are bounded structural checks, not a full decoder, sanitizer or malware scanner; production malware scanning, PDF/image processing isolation, storage encryption/access controls, retention and operational quotas are deployment prerequisites. No certification of arbitrary hostile file safety is claimed. File bytes and base64 are excluded from command journals (content hash is journaled).

The same-database design makes SQL backup/restore include attachment bytes and metadata in one consistent snapshot; the recovery rehearsal must verify content hashes and restored access. No filesystem attachment directory needs separate copying in this slice. External object storage would require a new consistency design.
